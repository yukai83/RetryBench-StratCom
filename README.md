# RetryBench–StratCom

Code, results and paper sources for *When Does Waiting Help? Observable-History Retry Control for API-Dependent Agentic AI Workflows* (five-page IEEE conference paper, prepared for ICNGN 2026).

**Repository:** https://github.com/yukai83/RetryBench-StratCom

**Status:** synthetic research prototype. It is not operational guidance or field validation, and it implies no institutional endorsement.

## What the study does

A seeded discrete-event simulator runs three strategic-communications reporting workflows and five retry policies under injected faults. The study has four parts:

1. **Label-masking control** (Table I). The same outages are shown to a policy either with their cause visible or as a generic 5xx.
2. **Main study** (Tables II–III, Fig. 2). A three-parameter observable-history controller is tuned on development seeds and frozen. It is then compared with four baselines on held-out conditions, unseen graph shapes and real localhost HTTP requests (Table V).
3. **Post-hoc diagnostics** (Table IV, Fig. 3 and Section V). These cover an outage-length sweep, a history-window sweep, a detector check scored against the hidden outage label, a switching ablation (the controller against its own two waits used alone and against perfect detection, an upper bound that reads the hidden label), a wider tuning grid, a deadline-guard ablation and how often the proxy's call cap binds.
4. **Checks.** An audit script reconciles every saved result. A verification script recomputes every number quoted in the paper's text from the data and the code.

## Reproduce

Requires Python ≥ 3.10 with `numpy`, `matplotlib` and `pytest`; `pdflatex` with IEEEtran for the paper; `pandoc` and `python-docx` for the optional Word copy.

```bash
python -m pip install -e '.[test,study]'
python -m pytest -q                  # 87 tests
python run_label_masking.py          # Table I                  -> results/label_masking/
python run_main_study.py             # tuning, freeze, held-out -> results/main/
python run_window_sweep.py           # Section V-E              -> results/main/
python local_http_benchmark.py       # Table V, real sockets    -> results/main/
python run_diagnostics.py            # Table IV, Fig. 3         -> results/diagnostics/
python audit_results.py              # reconciliation           -> results/audit.json
python make_tables.py && python make_figures.py
python verify_paper_numbers.py       # every number in the text vs. the data and the code
pdflatex main.tex && pdflatex main.tex
python build_word.py                 # optional editable Word copy (run after pdflatex)
```

Simulated results are deterministic for a given Python version. The localhost HTTP timings vary with OS scheduling, but the outcomes do not.

## Conditions

All held-out, development and sweep conditions mask outages as a generic 5xx. Background errors are IID per attempt.

| Use | Condition | Deadline | Background errors | Other |
|---|---|---|---|---|
| Label-masking (Table I) | `outage_45` | 45 s | 8% | unextended outages, label visible or masked |
| Development | `dev_iid` | 22 s | 22% | |
| Development | `dev_outage` | 45 s | 7% | unextended outages |
| Development | `dev_quota` | 55 s | 8% | hinted quota 1.8 req/s, burst 2 |
| Held-out | `held_iid_27` | 26 s | 27% | |
| Held-out | `held_outage_extended` | 48 s | 10% | both outage windows +2 s |
| Held-out | `held_tight_17` | 14 s | 17% | |
| Held-out | `held_quota_23` | 52 s | 9% | hinted quota 2.3 req/s, burst 2 |
| Held-out | `held_mixed` | 40 s | 20% | plus 2% permanent errors |
| Unseen graphs | `newgraph_iid` / `newgraph_outage` | 50 s / 55 s | 23% / 10% | outage windows unextended |

Outage windows: 6.5 s starting at 4.5–7.5 s and 3.0 s starting at 19–23 s (per seed). The history window `W` = 6 s was set before tuning, just under the first outage window; `run_window_sweep.py` tests 2 and 12 s.

## Files

- `main.tex`, `main.pdf`, `tables/`, `figures/`: the paper. Tables and figures are generated by `make_tables.py` and `make_figures.py`; Fig. 1 is drawn from the IEA template in `retrybench/stratcom.py`, and Table III's caption reads its deadlines and error rates from the scenario definitions. `RetryBench_StratCom_Editable_Two_Column.docx` is an editable working copy, not a byte-exact IEEEtran replica. Its equations render in Microsoft Word, but some other viewers leave inline math blank.
- `retrybench/`: simulator, workflows, scenarios and retry policies. `tests/`: unit and regression tests.
- `results/label_masking/`, `results/main/`, `results/diagnostics/`: per-seed CSVs, summaries, the frozen configuration (`results/main/frozen_parameters.json`) and manifests.
- `results/audit.json`: output of `audit_results.py`.

## Boundaries

The workflows are synthetic toy information-assessment procedures, not data from any organisational system. A successful checking task shows only that a simulated tool call ran; it does not show a claim is true. Outages are exogenous, so retry-induced overload is not modelled. Do not apply retries to side-effecting tools without idempotency protection.
